# 2026-07-07 工作日志

## 修复：任务列表加载失败（前端 JS 变量声明顺序错误）

### 问题现象
- 用户修改了项目代码（新增文档预览功能）后，登录网页发现"加载任务列表失败"
- 数据库连接正常，后端 API（/jobs、/auth/bootstrap）均返回 HTTP 200

### 根本原因
- 文件：`static/index.html` 中 `renderTaskItems` 函数内
- `sourcePreviewBtn` 和 `outputPreviewBtn` 变量在声明时引用了 `baseName`
- 但 `baseName` 的 `const` 声明位于这两个变量**之后**
- JavaScript `const` 变量在声明前处于"暂时性死区"（TDZ），访问会抛出 `ReferenceError`
- 后端 API 对每个任务都返回 `source_preview_url`（非空字符串），导致三元表达式 true 分支必然执行
- 异常被 `catch(e)` 捕获，前端显示"加载任务列表失败"

### 修复方式
- 将 `baseName` 声明移动到 `sourcePreviewBtn` 和 `outputPreviewBtn` 之前
- 删除原位置（`iconHtml` 之后）的 `baseName` 声明

### 注意事项
- 项目有两个 Python 环境：
  - `D:\python3.13\python.exe`（有 uvicorn 等依赖，用于运行服务）
  - `C:\Users\SFJT\.workbuddy\binaries\python\versions\3.13.12\python.exe`（managed，无项目依赖）
- `/health` 端点始终报 `db: unreachable`，因为代码使用 `auth_store._engine`（下划线前缀），但 AuthStore 类的属性名是 `self.engine`（无下划线），这是 health 端点的 bug，不影响实际功能
- 服务启动命令：`D:/python3.13/python.exe -m uvicorn webapp:app --host 0.0.0.0 --port 8000`
- index.html 在服务启动时一次性读入内存（`INDEX_HTML = ...read_text()`），修改后需重启服务
